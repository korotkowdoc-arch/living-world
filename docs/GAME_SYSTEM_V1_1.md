# THE LIVING WORLD — GAME SYSTEM V1.1
## Игровая оболочка и защита от сюжетного зацикливания

**Статус:** рабочий регламент поверх существующего приложения и OAuth MCP-моста. Это не отдельная модель, не автоматическая симуляция во время молчания пользователя и не обязательный OpenAI API.

### Основной режим

Художественная история от третьего лица — единственный обязательный видимый поток. Гарри автономен, NPC самостоятельны, значимые сцены ведутся крупно и до естественной драматической точки. Никто не ждёт после каждой реплики выбора из меню. «На это:» меняет только текущую валидную цепочку; аннулированный хвост никогда не становится памятью.

**Режиссёрский пульт скрыт**, пока пользователь сам не запросил его. Через действующий OAuth-мост можно вызвать `get_narrative_pacing`, `get_world_depth`, `get_causal_memory`, `get_npc_offscreen_brief` и другие уже существующие запросы. Видимые игровые показатели не вставляются посреди художественной сцены.

### Слои симуляции

1. **Календарь и окружающий мир.** Время движется причинно: учебное расписание, поездки, работа, здоровье, обязательства и доступные ресурсы. PROJECT YEAR ANCHORS — календарные/причинные возможности, не гарантия канонических результатов. При пересечении даты модель проверяет событие самостоятельно, даже если пользователь не напомнил; события, ставшие невозможными из-за AU, не форсируются.
2. **Самостоятельные NPC.** Их планы, доступные знания, связи, страхи и возможности существуют вне камеры. Внекадровое событие фиксируется только при реальной возможности и каузальном основании; его нужно отличать от плана. Кандидат на событие — не событие.
3. **Отношения и взрослая частная жизнь.** Привязанность, уважение, раздражение, влечение, конфликт, забота и сексуальность — независимые измерения, а не один процент. Они развиваются через обстоятельства. Нельзя вымораживать близость из истории только потому, что открыт квест; нельзя принудительно вводить свидание или секс по таймеру. Персонажи обладают собственными границами.
4. **Умения, магия, здоровье, имущество.** Навыки требуют практики и времени; травмы и ресурсы не обнуляются. Денежные и предметные события записываются только после подтверждённого действия, по установленному источнику.
5. **Сюжетные процессы.** Долговременная линия имеет устойчивый ID, цель, ставки, причинные основания, статус active/paused/resolved/archived. Служебная загадка не обязана становиться главным сюжетом.
6. **Сохранения и развилки.** Действующая ветка определяется подтверждёнными предками текущей сцены, не всей историей репозитория/мира. Checkpoint — полный снимок необходимого состояния, не только последние изменения. Новая игра создаётся как новый мир/ветка с начальным фундаментом; прежние сыгранные сцены, деньги и связи не переносятся.

### Почему старый Y1 зациклился

В завершённом историческом прогоне мельчайшие уточнения архивной загадки получали подробные сцены, а новогодние, зимние и весенние узлы основного года сводились к краткому переходу. Это пример **сбоя распределения внимания**, а не причина вычеркнуть расследования совсем.

### Порядок выбора следующей сцены (скрытая процедура)

Перед каждой сценой, в таком порядке:

1. Восстановить действующую ветку, точное доступное время и физическое/психологическое состояние, документы, знания каждого, актуальные действия и цели персонажей.
2. Проверить ближайшие календарные процессы. Важный календарный узел не ждёт напоминания пользователя, но его исход не зафиксирован.
3. Проверить, продолжается ли непосредственно уже действующая цельная сцена. Разговор, бой или интимный эпизод не обрывается ради переноса камеры/баланса.
4. Рассмотреть несколько самостоятельных причинных направлений: основной сюжет, частная жизнь, отношения, магическое развитие, бытовые и институциональные события, конфликты и тайны.
5. Использовать **сигналы внимания** из `narrative_pacing` как основания проверить ситуацию, не как обязательный алгоритм выбора: три последовательных эпизода с одним подтверждённым фокусом, две безрезультатные попытки проверить одну загадку, отсутствие меток в иных направлениях.
6. Выбрать следующую сцену по доступным обстоятельствам и индивидуальной инициативе героев. Если новое действие/улика не имеет причинного основания — не писать его. Если ветка в тупике — дать ей ждать.
7. После сцены сохранить **только действительно произошедшую дельту**, добавить `narrative_beats` при наличии дословного доказательства и обновить причинные линии.

### Как учитывается темп в коде

- Новый модуль: `public/narrative-pacing.mjs`.
- Для каждого подтверждённого эпизода может быть записан `changes.narrative_beats` — максимум четыре метки. Пример:
  ```json
  {
    "narrative_beats": [{
      "domain": "investigation",
      "progress": "stall",
      "evidence": "Гарри перестал расспрашивать женщину.",
      "thread_id": "lia-record"
    }]
  }
  ```
- `domain`: `main`, `investigation`, `relationship`, `character`, `everyday`, `institutional`.
- `progress`: `advance` (реальное продвижение), `quiet` (жизнь идёт, без продвижения глобальной цели), `stall` (попытка без результата).
- `evidence` должен **буквально присутствовать** в литературном тексте текущей сцены. Слабая или притянутая цитата не гарантирует семантическую правильность метки: автоматический анализатор проверяет только источник и форму, а режиссёр может корректировать калибровку.
- Старые сцены без этой разметки **не классифицируются автоматически по словам**. Отсутствие метки не означает, что отношений или событий не было.
- Пульт выводит окно последних 12 сцен, количество размеченных/неразмеченных, повторяющиеся фокусы, возможные тупики и области, которые стоит перепроверить. Не назначает уровни любви, не создает сюжет и не «выдаёт квест».
- Если полная валидная цепочка недоступна (например, частичное восстановление из checkpoint), `complete=false`: система не выдаёт неполную историю за достоверную.
- Порог «две попытки» означает **проверить разумность паузы**, а не обязательное закрытие/отмену линии. Важная угроза способна оправдать продолжение.
- Порог «три сцены» означает **обзор приоритетов**, а не обязательный переход к свиданию или квесту.
- `get_scene_preflight`, `get_story_context` и `get_world_state` передают сигналы и подсказки ChatGPT; отдельный `get_narrative_pacing` открывает сведения только по запросу режиссёра. Обычная литературная сцена не показывает пульт автоматически.

### Запуск с нуля

Создать **новый мир** через существующий мастер и выбрать необходимые фундаментальные документы. Прежние завершённые Year Documents оставить архивом отдельного прогона, не копировать в новый мир. Утвердить Генезис. Запустить историю обычной сценой в ChatGPT через preflight и существующий механизм сохранения; дополнительный платный API не требуется.

### Известные ограничения

- Модель всё ещё способна ошибаться в выборе сцен и в собственных метках: невозможно программно гарантировать отсутствие скучной серии по текстовому корпусу.
- Точное выполнение PROJECT YEAR ANCHORS требует актуальных проектных источников; анализатор **не превращает свободный текст календаря в строгий планировщик дат**. Это следующий отдельный этап развития.
- Значение `narrative_beats` хранится как источник-связанная аннотация, но сама по себе не устанавливает новые факты, знания, отношения и события за кадром.
- Пока ChatGPT не отвечает, мир не живёт асинхронно; после каждого запроса время продвигается в пределах подтверждённой сцены/симуляции.
- Для чтения нового MCP-инструмента нужно развернуть обновлённый bridge и обновить доступные инструменты соединения. До этого обычные запросы из PWA уже могут использовать новый prompt без API.
