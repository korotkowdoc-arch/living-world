# NPC Life V1 — самостоятельная жизнь и социальные связи

## Цель

Персонажи должны иметь собственные цели, ограничения, отношения, занятия и решения **независимо от камеры Гарри**. Нельзя стирать их жизнь на десятки сцен, пока главная камера расследует загадку. При этом никакого механического «каждые три сцены — секс» и никаких событий из воздуха.

Этот этап подключает существующую глубокую психологическую память к `Scene Director V2`. Новая версия не создаёт фонового игрового сервера: когда ChatGPT не работает, время не моделируется. Всё происходит при переходе между сценами, на основе подтверждённых ресурсов, временного промежутка и индивидуальной инициативы.

## Почему предыдущая версия была недостаточной

Существующий `projectCharacterMemory` корректно восстанавливал актуальные цели, состояние и знания NPC из валидной цепочки. `projectWorldDepth` сохранял направленные многомерные отношения и `npc_intentions`. Однако `buildDirectorFor` использовал по умолчанию в основном исходные карточки `base.characters`, а не полную восстановленную память, и планировщик не видел истории смены планов. Теперь `companionState` передаёт `npc_life` из текущей памяти персонажей и `depth_memory`.

## Подтверждённые планы NPC и их жизненный цикл

План, записанный в `npc_intentions`, становится историческим намерением, **не совершённым действием**. Сам по себе план не обязан исполниться. Он может устареть, быть заблокирован, оставлен или завершён только при причинном подтверждении.

Новое необязательное поле `changes.npc_plan_updates`:

```json
{
  "npc_plan_updates": [
    {
      "intention_id": "plan-home",
      "actor": "Лия",
      "status": "paused",
      "reason": "Устала и решила вернуться к разговору утром",
      "basis": "scene",
      "evidence": "Дословная реплика или действие, уже написанное в этой сцене"
    }
  ]
}
```

Статусы: `active`, `paused`, `blocked`, `completed`, `abandoned`, `superseded`. **Старый план без нового подтверждённого статуса остаётся `unresolved`** — это не обязательно активный план, но и не исполнение. Для события, произошедшего в новом промежутке за кадром, вместо `evidence` можно использовать `basis: "offscreen"` и `related_offscreen_id` из `npc_offscreen` **того же персонажа и этой же сцены**.

Валидация:
- Проверяется конкретный ID старого намерения и совпадение владельца плана.
- Закрытое/оставленное намерение не возобновляется автоматически; новый план требует нового основания и ID.
- Текст сцены должен содержать дословное подтверждение либо запись реального события NPC в том же `changes`.
- Планы и их изменения пересчитываются только из действующей ветки; аннулированные после «На это:» не переходят в другие ветви.
- При неполной памяти обновлять старые планы нельзя.

## Социальная модель

Действующий `projectWorldDepth` уже хранит направленные значения `trust`, `respect`, `affection`, `irritation`, `fear`, `attraction`, `loyalty`, `resentment`, `comfort`, `jealousy`, `solidarity`, `distance`. Эта версия использует их для обзора самостоятельных встреч, конфликтов и личных инициатив.

Это **не числовые баллы** и не инструкция сближать всех персонажей. Человек может доверять другому, испытывать раздражение и желание одновременно; обе стороны отношений могут чувствовать разное. Записывай изменения только после реального взаимодействия или подтверждённого внекадрового события. Отношения могут развиваться на главной камере, во внекадровых подтверждённых действиях и в параллельных сценах. Нельзя выдавать предположение о чувствах как объективное знание другого персонажа.

## Взаимодействие с Scene Director

`public/npc-life.mjs` формирует `npc_life` с подтверждёнными текущими целями, местом, здоровьем, планами и направленными связями. Умершие персонажи не могут быть кандидатами на действие. Режиссёр видит лишь причинно доступные **возможности**, не готовые события.

`Scene Director` рассматривает их параллельно с календарём и главным сюжетом, без жёсткого ранжирования. Если непрерывная сцена важна прямо сейчас, не нужно её прерывать. Отсутствие показанных отношений в последних сценах — сигнал исследовать подходящие обстоятельства, а не приказ создавать свидание.

Не передавай Гарри секреты NPC из режиссёрской камеры. Знания героев фиксируются только по реальным каналам.

## Интерфейс и инструменты

- Скрытый блок **«Режиссёрский пульт»** в PWA отображает актуальные цели, незакрытые планы и наличие направленных отношений.
- `get_scene_preflight` получает `scene_director.npc_life`, а `npc_autonomy.live_profiles` даёт отдельный ограниченный обзор.
- `get_story_context`, `get_world_state` и `get_scene_director` используют тот же подтверждённый `npc_life`.
- Новый **read-only** `get_npc_life` доступен для просмотра по запросу режиссёра после развёртывания OAuth-моста. Открытие пульта ничего не записывает в мир.
- Модель по-прежнему сохраняет `npc_offscreen` с реальными датой, целью, последствиями и каналом знания, а обновление `npc_plan_updates` фиксирует судьбу старого намерения.

## Технические ограничения

- Проверка точной цитаты доказывает лишь наличие цитаты, но не всю психологическую правдоподобность изменения.
- Состояние и планы воспроизводятся из сцен. Старые неразмеченные годы не реконструируются по догадкам.
- Путь между местами, расписание и возможность новой встречи всё ещё требует причинной оценки модели; отдельный строгий scheduling engine — дальнейший этап.
- Когда модель не вызвана, NPC не живут «сами в фоне». Можно запустить временной шаг вручную, и только после утверждения изменения становятся каноном.
- Проект остаётся **subscription-first**: никакой дополнительный платный API вызов для анализа NPC не требуется.
- Чистая новая игра требует нового мира и фундаментальных документов, без старого YEAR_DOCUMENT Y1 прошлого прогона.

## Проверка

`test/npc-life.test.mjs` проверяет принадлежность планов персонажам, ветвления, терминальные статусы, точные цитаты, связь с `npc_offscreen`, актуальные цели и сосуществование доверия и раздражения. GitHub Actions запускает тесты наряду с существующей регрессией.

Публичный `/health` подтверждает доступность Worker, но **не гарантирует**, что новый MCP-инструмент уже опубликован. Production smoke дополнительно проверяет точные имена инструментов `get_scene_director`, `get_narrative_pacing`, `get_npc_life`. В ChatGPT список инструментов может потребовать обновления/переподключения.
